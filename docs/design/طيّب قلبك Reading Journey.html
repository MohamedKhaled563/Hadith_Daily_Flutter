الخلاصة

ميزة واحدة اسمها رحلتي، بقاعدة واحدة: المكافأة للقراءة المتأنية، وفتح التطبيق وحده لا يعطي شيئاً.

الرسائل تُفتح كل يومثلاث خطوات تربط كل شيء: اقرأ رسالة اليوم، ثم حديثها وشرحه، ثم اكتب رسالتك. حلقة في الرئيسية تعرض الثلاث.
المكافأة تحتاج قراءة حقيقيةرسالة اليوم تحفظ السلسلة (streak). الحديث بشرحه وحده ينمّي الشجرة ويعطي النقاط الكبيرة.
التقدم شجرة من 42 ورقةكل ورقة حديث حقيقي تفتحه بلمسة. تناسب شعار القلب والورقة، ولا تحتاج مكتبة رسوم.
نقاط ولوحة أسبوعيةنقاط بحد أقصى للقراءة والحفظ والكتابة. لوحة اختيارية تصدر كل جمعة، ولا يتجاوز الحد إلا الرسائل التي قبلها المشرف.
الكاتب يرى أثرهالرسالة المقبولة تدخل الرسائل اليومية، فنخبر صاحبها كم قارئاً وصلت إليه. هذا أقوى دافع للكتابة، وبياناته موجودة.
إضافة الحفظالأحاديث كلها تُقرأ في نحو 2.2 ساعة، فحديث يومياً ينتهي في ستة أسابيع. المراجعة المتباعدة تُبقي سبباً يومياً نحو تسعة أشهر.
خطة مجانية بلا serverFirestore للتقدم لكل حساب، والتذكيرات على الجهاز، واللوحة تُنشر من الـdashboard. وبهذا تبقى كل وعود المتجر.
المشاركة دعوةصور بحجمين، وحفظ صورة، ورابط، ونسخ نص، وتصل كل التطبيقات. البطاقة تبدأ بالحديث والشجرة، والاسم مخفي افتراضياً.

حلقة العادة

الثبات أهم من الكثرة، كما في الرواية المشهورة «أحب الأعمال إلى الله أدومها وإن قل». القراءة اليومية القليلة هي التصميم كله.

اقرأ رسالة اليومتحفظ السلسلة وتملأ أول جزء من الحلقة. 2 نقطة.
اقرأ حديثهايمتلئ الخيط الذهبي وتصير الورقة ذهبية. 10 نقاط.
اكتب رسالتكدعوة بعد الحديث تفتح شاشة الكتابة. 15 نقطة بعد القبول.
انظر النتيجةالأرقام القياسية، ووصول رسالتك، ولوحة الجمعة، وتذكير الغد.

ما نبنيه

  • السلسلة (streak): تحفظها قراءة رسالة اليوم، وتُحسب من الأيام الفعلية، وبجانبها أفضل رقم لك. تم
  • أيام السماح (grace days): يوم لكل 7 أيام محسوبة، بحد يومين، وتُستخدم تلقائياً. يوم فائت واحد قليل الأثر على العادة، والتكرار هو المؤثر. تم
  • السهر محسوب: يوم القراءة يبدأ 03:00 بالتوقيت المحلي. تم
  • أنت مقابل نفسك: هذا الأسبوع مقابل الماضي تم، مع 8 أرقام قياسية Phase 3. شاشة الإتمام تعرض ما تحطم للتو، وهذه المفاجأة هي ما يعتمد عليه الدوبامين.
  • حصاد الجمعة: ملخص أسبوعي في التذكير والتطبيق. Phase 3
  • الدورة الثانية: بعد 42 تبدأ الشجرة موسماً جديداً، وتُحسب إعادة القراءة. Phase 5

ما نتركه عمداً

  • نقاط الإعجابات: تشجع تبادل الإعجاب بين الحسابات.
  • عدّاد الحسنات: النقاط تقيس النشاط في التطبيق، ولا تدّعي قياس الأجر.
  • الجوائز: تجلب قواعد مسابقات المتاجر، وتعطي سبباً للغش.
  • إشعار الذنب: لا «ستخسر»، ولا شخصية حزينة.
  • ألقاب مثل حافظ أو إجازة: لها معنى علمي لا يمنحه التطبيق.
  • اختيار من متعدد أو ترتيب نص الحديث: الخيارات الخاطئة تضع كلاماً مخترعاً بجانب كلام النبي ﷺ.

كيف تعمل اللوحة Phase 4

  • اختيارية: مغلقة افتراضياً. يظهر القارئ باسمه أو باسم «فاعل خير» الموجود في تطبيقك.
  • ثلاث قوائم: أعلى نقاط، وأكثر رسائل مقبولة، والحفظ بعد Phase 5.
  • مرة في الأسبوع: الجمعة مساءً يفتح المشرف تاباً جديداً في الـdashboard، يراجع الأسماء الأولى، يحذف المريب، وينشر.
  • أول 10 فقط: الباقون يرون نقاطهم مقابل الأسبوع الماضي، بلا رقم ترتيب.
  • بداية جديدة كل سبت: تُصفَّر النقاط ويبدأ أسبوع جديد.
  • تكلفة قليلة: النشر يقرأ نحو 50 document أسبوعياً، وكل هاتف يقرأ document واحداً.
  • تبدأ عند وجود عدد كافٍ: ننتظر نحو 50 قارئاً في الأسبوع، فلوحة بخمسة أسماء تبدو فارغة.

ما الغش الممكن؟

القراءة والحفظ يحدثان على الهاتف، فلا server يثبتهما. تطبيق معدّل يستطيع ادعاء 300 نقطة كاملة، لكن القارئ النشط الصادق يصل إلى الحد نفسه، فلا يتقدم الغاش عليه. الرسائل المقبولة وحدها ترفع فوق الحد، والمشرف يقرأ كل واحدة. لذلك قائمة المشاركة موثوقة، وقائمة الحفظ قائمة على الثقة.

الحفاظ على الروح الصحيحة

نصحتك سابقاً بعدم وضع لوحة، وقرارك قابل للتطبيق: للتنافس في الخير أصل واضح («وفي ذلك فليتنافس المتنافسون»)، ومسابقات الحفظ مألوفة لقرائك. الخطر المتبقي هو الرياء، لذا نلتزم بهذه القواعد:

  • نسميها نقاطاً، بلا حسنات أو أجر، وبلا عناوين مثل «الأفضل».
  • الانضمام اختياري، و«فاعل خير» متاح دائماً.
  • المراجع يوافق على اسم اللوحة وصياغتها واستخدام الآية.

مسودة security rules للنقاط (تُختبر بـ verify_rules.py قبل الاستخدام) 
// weeks start Saturday 00:00 UTC
function weekNow() {
  return math.floor((request.time.toMillis() - 172800000) / 604800000);
}
function validOwnScore() {
  let d = request.resource.data;
  let sameWeek = resource != null && resource.data.week == d.week;
  return d.keys().hasOnly(['week','device','memo','approved','score',
                           'name','show','updatedAt'])
    && d.week == weekNow()
    && d.device is int && d.device >= 0 && d.device <= 300
    && d.device <= (sameWeek ? resource.data.device : 0) + 60
    && d.approved == (sameWeek ? resource.data.approved : 0)
    && d.score == d.device + d.approved * 15
    && d.name is string && d.name.size() <= 100 && d.show is bool
    && d.updatedAt == request.time;
}
match /scores/{uid} {
  allow read: if request.auth != null
              && (request.auth.uid == uid || isModerator());
  allow delete: if request.auth != null && request.auth.uid == uid;
  allow create, update: if request.auth != null
              && ((request.auth.uid == uid && validOwnScore()) || isModerator());
}

لماذا تكفي التذكيرات على الجهاز

القراءة تتطلب فتح التطبيق، وكل فتح يعيد بناء الجدول. فالمواعيد القادمة تُكتب لحالة عدم عودة القارئ، ولو عاد تُستبدل. بهذه الفكرة نحصل على تذكيرات شخصية بلا server، وتعمل دون إنترنت.

ما نبنيه تقنياً (7 بنود)
  • Planner: دالة خالصة planSlots(snapshot, now) تعيد العنوان والنص والرابط والقناة لكل موعد. تحل محل العناوين الثابتة في notification_scheduler.dart:387 و:401.
  • تحديث سريع: بعد كل حديث مكتمل نعيد كتابة مواعيد اليوم والغد فقط.
  • اللمس يفتح المكان الصحيح: الـpayload يحمل hadith:16 أو review:5 أو harvest. حالياً _onNotificationResponse يتجاهله، والتشغيل البارد (cold start) يحتاج المعالجة نفسها.
  • لكل مستخدم: نعيد بناء الجدول عند كل دخول وخروج، فلا يظهر تقدم الشخص السابق على شاشة هاتف مشترك.
  • تحكم القارئ: قناة Android جديدة reading_journey لكتم رسائل التقدم وإبقاء اليومية.
  • الإذن: نطلبه بعد أول رسالة مفتوحة أو حديث مكتمل، وليس عند أول تشغيل.
  • أخبار الكاتب: إشعارات القبول والوصول تظهر حين يلاحظها التطبيق، خارج الموعدين. هي نادرة، وقراءة واحدة يومياً تكفي لها.

المشاركة

يشارك القارئ تقدمه في أي مكان، لكن إعلان التقدم في العبادة قد ينزلق إلى الرياء. لذا كل بطاقة دعوة: الحديث والشجرة أولاً، والأرقام صغيرة، والاسم مغلق حتى يفتحه القارئ. الصياغة النهائية عند المراجع.

ما يمكن مشاركته

الحديث المكتمل، والشجرة، والـmilestones (قراءة وحفظ)، وحصاد الجمعة، وبطاقة ختم الأحاديث الـ42 باسم وتاريخ اختياريين، وتأمل شخصي، ودعوة بسيطة للقراءة معاً.

السعة على الخطة المجانية

تقديري 9 عمليات كتابة و11 قراءة لكل قارئ نشط يومياً، شاملة تحديث النقاط. حد 20,000 كتابة يومياً يكفي نحو 2,200 قارئ يومي، ناقص ما يكتبه التطبيق حالياً. عند بلوغ الحد يتوقف Spark عن الاستجابة، فيتعطل المجتمع والإعجابات أيضاً.

الخطة: ننتقل إلى Blaze عند نحو 1,000 قارئ يومي، مع budget alert. عند 10,000 قارئ يومي تكلف هذه الميزة نحو 5$ شهرياً بأعلى الأسعار المنشورة. المصادر تختلف في الأسعار، فتأكد منها من صفحة Google.

إصلاح قراءة رسائل التذكير، مدموج في PR #2: كل تحديث كان يقرأ كل رسالة نشطة. مع 200 رسالة و1,000 قارئ يحدّثون 1.5 مرة يومياً، تصبح 300,000 قراءة يومياً، أي ستة أضعاف الحد المجاني. الآن القائمة غير المتغيرة تكلف قراءة واحدة. نجحت 65 اختبار scheduler وlifecycle على محاكي Android. إيقاف رسالة أو حذفها من الـdashboard صار يُعلم الهواتف بالتحديث، ولم يُجرَّب هذا المسار على مشروع حي بعد.

لماذا تبقى صحيحة

  • السلسلة تُحسب ولا تُخزن. تأتي من قائمة الأيام، فلا تختلف بين الهواتف.
  • الكتابة تدمج الحقول. هاتفان offline لا يمسح أحدهما تقدم الآخر.
  • كل كتابة تتكرر بأمان. offline queue في Firestore يتعامل مع ضعف الاتصال.
  • بيانات الزائر تُدمج مرة واحدة. الدخول يضم التقدم المحلي للحساب ثم يمسحه من الهاتف.

المطلوب معها

  • Security rules: للمالك فقط، بأسلوب المفضلة ومع حدود للحجم، ولا يقرؤها المشرفون. منشورة
  • حذف الحساب: نضيف المجموعات الجديدة وscores/{uid} إلى deleteAccount، لأن Firestore لا يحذف تلقائياً. الاسم المنشور يبقى حتى لوحة الجمعة التالية، والسياسة يجب أن تذكر ذلك. الرحلة تمت scores في Phase 4
  • مزامنة النقاط: الهاتف يحسب نقاط الأسبوع من سجل الأيام ويستبدل الـdocument، والمحاولات offline تُعاد عند الفتح التالي.
  • رصيد القبول: زر القبول في الـdashboard يضيف النقاط في الـbatch نفسه، وإخفاء المنشور يزيلها.
  • استثناءات الفهارس: days وhadith وmemo في firestore.indexes.json. منشورة
  • القانوني: سياسة الخصوصية، وdelete-account.html، ونموذجا الخصوصية في المتجرين. الملفات تمت حدّث النموذجين عند الإرسال.
الـrules المنشورة للرحلة 
// inside match /users/{uid}, beside /favorites
match /journey/{docId} {
  allow read, delete: if request.auth != null && request.auth.uid == uid;
  allow create, update: if request.auth != null && request.auth.uid == uid
    && docId == 'state'
    && request.resource.data.keys().hasOnly(['v','round','startedOn','hadith',
         'memo','seen','records','prefs','updatedAt'])
    && request.resource.data.updatedAt == request.time
    && (!('hadith' in request.resource.data)
        || request.resource.data.hadith.size() <= 42)
    && (!('memo' in request.resource.data)
        || request.resource.data.memo.size() <= 42);
}
match /journeyYears/{year} {
  allow read, delete: if request.auth != null && request.auth.uid == uid;
  allow create, update: if request.auth != null && request.auth.uid == uid
    && year.matches('^[0-9]{4}$')
    && request.resource.data.keys().hasOnly(['days'])
    && request.resource.data.days.size() <= 366;
}
